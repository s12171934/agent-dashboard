# wireframes — 대시보드 와이어프레임 보드

대시보드를 다시 설계하면서 그리는 와이어프레임을 모아 두는 곳이다. 보드(`index.html`) 한 장에서 모든 화면을 모든 폭으로 한꺼번에 본다.

- **보는 곳:** `https://dashboard.s-dante.com/wireframes/` (웹 전용). 대시보드 화면과 macOS·iPhone 앱 어디에도 링크하지 않는다. 서비스 워커가 건드리지 않고, 검색 엔진에는 `noindex` 로 빠진다.
- **공개 주소다.** 실제 세션 제목·티켓 키·PR 제목·프롬프트 같은 실제 데이터는 넣지 않는다. 현행 화면의 캡처도 올리지 않는다.
- **로컬:** `python3 scripts/dev-frontend.py` → `http://127.0.0.1:5500/wireframes/`. 화면 파일을 저장하면 보드에서 그 화면의 프레임만 다시 읽는다.
- **배포:** `main` 에 이 폴더가 바뀌면 `deploy-frontend.yml` 이 페이지와 함께 올린다(`scripts/deploy-frontend.sh` 가 `wireframes/` 로 복사하고, 이 README 는 뺀다).

## 보드

| 보기 | 무엇 |
| --- | --- |
| 격자 | 행은 화면, 열은 폭 — iPhone Duo 여섯 자세(접힘 466×678 · 접힘 가로 678×466 · 펼침 669×951 · 펼침 가로 951×669 · 반접힘 책 951×669 · 반접힘 노트북 669×951)와 태블릿 820×1180 · 데스크톱 1440×900 · 데스크톱 세로 1440×2560. 프레임마다 실제 폭으로 그린 와이어프레임을 배율만큼 줄여 보인다. 시안이 여럿이면 「나란히」는 시안마다 행을, 「하나씩」은 A·B 버튼으로 바꿔 본다 |
| 흐름 지도 | 홈에서 몇 단계 만에 닿는지로 화면을 열로(한 열에 4개까지) 격자에 늘어놓고, 화면 사이 이동을 화면 사이 빈 통로로만 지나는 꺾은선 화살표로 그린다(화살표마다 통로 안 자기 차선). 점선 화살표는 되돌아가는 길, 점선 테두리는 화면 안 링크로는 닿지 않고 공통 내비(사이드바·독·시트)로만 들어가는 화면 |

- 설정은 모두 왼쪽 사이드바에 있다(보기 · 폭 · 필터 · 프레임 · 화면 영역 · 플러그인 슬롯). `‹` 로 접고 `›` 로 편다. 좁은 창에서는 접힌 채로 시작하고 보드 위에 겹쳐 열린다.
- 「화면 영역」은 모든 화면에 공통인 부분(사이드바·레일 · 하단 탭 바 · 앱 상태 바 · 머리 줄 · 본문 · 반접힘 보조 시트 · 설계 메모 · 주름 선)을, 「플러그인 슬롯」은 화면들이 쓰는 `data-slot` 마다를 체크박스로 켜고 끈다. 끈 것은 모든 프레임(크게 보기 포함)에서 숨는다 — 보드가 프레임에 `<style>` 을 넣으므로 화면 파일에는 아무것도 달지 않는다.
- 프레임을 누르면 크게 열린다. 그 안에서 `data-to` 가 붙은 요소를 누르면 그 화면으로 넘어간다(클릭으로 흐름 따라가기).
- 「슬롯 경계 표시」를 켜면 플러그인이 채우는 영역(`data-slot`)이 점선과 이름으로 겹쳐 보인다.
- 「전체 길이」를 켜면 프레임이 한 화면 높이 대신 페이지 전체 높이로 늘어난다.
- 배율은 슬라이더나 ⌘/Ctrl + 휠. 고른 보기·폭·필터는 브라우저에 기억한다.

## 화면 추가 규칙 (Codex 워커용)

1. `screens/_template/a.html` 을 `screens/<화면 id>/<시안>.html` 로 복사한다. 시안 이름은 `a`, `b`, `c` …
2. `../../wf.css` 와 `../../wf.js` 만 붙인다. 다른 CSS 파일·JS·이미지·웹 폰트는 붙이지 않는다(그 화면에만 필요한 배치는 파일 안 `<style>` 로). 색은 회색과 `wf-tag`·`wf-dot` 의 상태색만.
3. 한 파일로 모든 폭을 그린다. 단계는 `wf.css` 머리 주석 — 휴대폰(≤500, Duo 접힘) · 펼침(Duo 펼침과 접힘 가로: 두 칸, 틈이 주름 위) · 태블릿 · 데스크톱 · 반접힘(`html[data-posture]`: 첫 반쪽 페이지, 둘째 반쪽 `.wf-half` 시트). 분기는 `wf-only-<단계>`·`wf-hide-<단계>`, 두 칸은 `wf-panes`. 셸(사이드바·독·시트)은 템플릿 그대로 두고 현재 화면에 `on` 만 옮긴다. iPhone Duo 폭에서는 `wf.js` 가 `html.wf-app` 을 켜 앱 셸(상태 바·하단 탭 바, 레일 없음)로 그린다 — 화면 파일에서 레일 폭을 보정하지 않는다.
4. 글자는 자리표시(「세션 제목」, 「PSQ-0000」)로 쓴다. 실제 데이터를 넣지 않는다.
5. 다른 화면으로 가는 요소에는 `data-to="<화면 id>"` 를 단다. 보드의 흐름 지도는 이것을 읽어 그린다. 공통 셸의 내비(사이드바·독·시트 첫 줄)는 `data-shell` 로 표시돼 있어 흐름에서 빠진다 — 템플릿 그대로 두면 된다. 와이어프레임이 없는 화면은 `screens.json` 의 `to`(현행 흐름)를 쓴다.
6. 설계 의도는 `<p class="wf-note">` 로 화면 안에 남긴다.
7. 화면 본문은 패널 모듈로 짠다 — `wf-grid12` 위의 `wf-module`(머리 `wf-mhead` · 본문 `wf-mbody`, `--span`·`--rows`, `data-slot="panel"`). 오케스트레이션은 `wf-seg`(분절 막대) · `wf-chip`(에이전트 칩) · `wf-dense`(밀집 표)와 상태 색으로 그린다. 규칙은 [FLOW.md](FLOW.md) 「모듈형 화면」·「오케스트레이션 시각화」.
7-1. 플러그인이 채우는 영역에는 `data-slot="<슬롯>" data-plugin="<플러그인 id>"` 를 단다(슬롯·플러그인 목록은 [FLOW.md](FLOW.md) 「컨셉」). 코어가 그리는 부분에는 달지 않는다. 보드의 「슬롯 경계 표시」가 이 경계를 보여 준다.
8. `screens.json` 의 그 화면 `variants` 에 `{ "id": "a", "file": "screens/<화면 id>/a.html", "status": "draft", "note": "한 줄 요약" }` 를 더한다. `status` 는 `draft`(시안) · `picked`(확정) · `dropped`(보류).

## 흐름 명세

화면마다 무엇을 먼저 보이고 무엇을 누르게 할지는 [FLOW.md](FLOW.md) 가 정한다. 와이어프레임은 그 명세를 브리프로 그린다.

## screens.json

- `widths` — 보드의 열. `w`·`h` 는 프레임 크기, `env` 는 그 폭을 쓰는 환경.
- `groups` — 화면 묶음(기본 탭 · 화면 · 상세 · 오버레이).
- `screens` — 화면 id·이름·묶음, `to`(현행 대시보드에서 이 화면이 이어지는 화면), `variants`(그린 시안).
