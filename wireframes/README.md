# wireframes — 대시보드 와이어프레임 보드

대시보드를 다시 설계하면서 그리는 와이어프레임을 모아 두는 곳이다. 보드(`index.html`) 한 장에서 모든 화면을 모든 폭으로 한꺼번에 본다.

- **보는 곳:** `https://dashboard.s-dante.com/wireframes/` (웹 전용). 대시보드 화면과 macOS·iPhone 앱 어디에도 링크하지 않는다. 서비스 워커가 건드리지 않고, 검색 엔진에는 `noindex` 로 빠진다.
- **공개 주소다.** 실제 세션 제목·티켓 키·PR 제목·프롬프트 같은 실제 데이터는 넣지 않는다. 현행 화면의 캡처도 올리지 않는다.
- **로컬:** `python3 scripts/dev-frontend.py` → `http://127.0.0.1:5500/wireframes/`. 화면 파일을 저장하면 보드에서 그 화면의 프레임만 다시 읽는다.
- **배포:** `main` 에 이 폴더가 바뀌면 `deploy-frontend.yml` 이 페이지와 함께 올린다(`scripts/deploy-frontend.sh` 가 `wireframes/` 로 복사하고, 이 README 는 뺀다).

## 보드

| 보기 | 무엇 |
| --- | --- |
| 격자 | 행은 화면, 열은 폭(휴대폰 390 · 태블릿 820 · 데스크톱 1440). 프레임마다 실제 폭으로 그린 와이어프레임을 배율만큼 줄여 보인다. 시안이 여럿이면 「나란히」는 시안마다 행을, 「하나씩」은 A·B 버튼으로 바꿔 본다 |
| 흐름 지도 | 홈에서 몇 단계 만에 닿는지로 화면을 열로 늘어놓고, 화면 사이 이동을 화살표로 그린다. 점선 화살표는 되돌아가는 길, 점선 테두리는 홈에서 닿지 않는 화면 |

- 프레임을 누르면 크게 열린다. 그 안에서 `data-to` 가 붙은 요소를 누르면 그 화면으로 넘어간다(클릭으로 흐름 따라가기).
- 「전체 길이」를 켜면 프레임이 한 화면 높이 대신 페이지 전체 높이로 늘어난다.
- 배율은 슬라이더나 ⌘/Ctrl + 휠. 고른 보기·폭·필터는 브라우저에 기억한다.

## 화면 추가 규칙 (Codex 워커용)

1. `screens/_template/a.html` 을 `screens/<화면 id>/<시안>.html` 로 복사한다. 시안 이름은 `a`, `b`, `c` …
2. 스타일은 `../../wf.css` 하나만 쓴다. 다른 CSS·JS·이미지·웹 폰트를 붙이지 않는다. 색은 회색과 `wf-tag`·`wf-dot` 의 상태색만.
3. 한 파일로 세 폭을 모두 그린다. 폭 분기는 `wf.css` 의 `wf-hide-phone`·`wf-only-phone`·`wf-hide-tablet`·`wf-only-tablet` 이나 파일 안의 `@media` 로.
4. 글자는 자리표시(「세션 제목」, 「PSQ-0000」)로 쓴다. 실제 데이터를 넣지 않는다.
5. 다른 화면으로 가는 요소에는 `data-to="<화면 id>"` 를 단다. 보드의 흐름 지도는 이것을 읽어 그린다. 와이어프레임이 없는 화면은 `screens.json` 의 `to`(현행 흐름)를 쓴다.
6. 설계 의도는 `<p class="wf-note">` 로 화면 안에 남긴다.
7. `screens.json` 의 그 화면 `variants` 에 `{ "id": "a", "file": "screens/<화면 id>/a.html", "status": "draft", "note": "한 줄 요약" }` 를 더한다. `status` 는 `draft`(시안) · `picked`(확정) · `dropped`(보류).

## screens.json

- `widths` — 보드의 열. `w`·`h` 는 프레임 크기, `env` 는 그 폭을 쓰는 환경.
- `groups` — 화면 묶음(기본 탭 · 화면 · 상세 · 오버레이).
- `screens` — 화면 id·이름·묶음, `to`(현행 대시보드에서 이 화면이 이어지는 화면), `variants`(그린 시안).
