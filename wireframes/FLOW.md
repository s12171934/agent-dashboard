# 와이어프레임 흐름 명세 (초안 1차)

대시보드를 다시 그리기 위한 작업 흐름·정보 구조(IA)·화면별 명세다. 와이어프레임(`screens/<id>/<시안>.html`)은 이 문서를 브리프로 그린다. 그림 규칙은 [README.md](README.md), 현행 기능의 상세는 저장소 [README.md](../README.md)의 해당 절을 본다.

## 근거 — 실제 사용 (최근 60일, `server/ausage`, 기록 4,934건)

| 환경 | 하는 일 | 근거 |
| --- | --- | --- |
| **Mac** (클릭 1,454) | QA 워크트리 리뷰 → 웹으로 보기 → 확인 → 머지. 그다음 에이전트, 설계문서 | 워크트리 리뷰 184회·화면 시간 40%, 「확인」 147 · 「웹으로 보기」 92 · 표시 82 · merge 73 |
| **iPad** (클릭 597) | 테스트를 지켜보다가 결정에 답한다 | 테스트 132회·45%, 에이전트 142회·29%, 결정 첫 선택지 72 |
| **휴대폰 · iPhone Duo** (웹) | 녹화 영상을 본다. 결정에 짧게 답한다 | 웹 휴대폰 화면 시간의 59%, 웹 태블릿 97% 가 녹화 영상 |
| 거의 안 씀 | 캐릭터·Run 상세·드라이버 상세 0회, 상호작용 4, 비교 8, 캔버스 11, 플랜 사용량 11 | |

## 원칙

1. **「내 차례」가 먼저다.** 사람이 답해야 하는 것(결정·보고 확인·반출 승인·막힘)은 어느 화면에서든 한 번에 닿는다. 홈의 맨 위, 내비게이션 「결정」 배지.
2. **환경마다 시작 화면이 다르다.** Mac 은 리뷰, iPad 는 테스트+결정, 휴대폰은 결정·녹화 영상으로 바로 간다. 홈은 이 셋으로 가는 갈림길이다.
3. **목록 → 상세는 같은 화면에서.** 넓은 화면(펼침·태블릿·데스크톱)은 왼쪽 목록 + 오른쪽 상세 두 칸(`wf-panes`), 좁은 화면(Duo 접힘·반접힘의 페이지 쪽)은 목록에서 상세로 넘어간다.
4. **드물게 쓰는 화면은 숨기지 않고 한 단계 뒤로.** 「더 보기」에 모은다. 지우지 않는다(이번 초안의 범위 밖).
5. **화면은 결정·행동 단위로 짠다.** 숫자 타일보다 「지금 누를 것」이 먼저 보인다.

## 컨셉 — 얇은 코어 + 플러그인 패키지

대시보드는 **에이전트 세션을 보는 얇은 코어** 위에, 기능마다 하나씩 **플러그인 패키지**를 붙여 만든다. 코어는 화면을 거의 갖지 않고 「자리(슬롯)」만 낸다. 결정·테스트·QA 리뷰 같은 화면과 세션 카드의 배지, 홈 타일, 「내 차례」 항목은 모두 플러그인이 그 자리에 넣는다. 쓰지 않는 기능은 플러그인을 빼면 화면에서도 수집에서도 사라진다.

### 코어가 가진 것 (이것만)

| 코어 | 무엇 |
| --- | --- |
| 셸 | 내비게이션 틀, 라우팅, 레이아웃 단계(Duo 접힘·펼침·반접힘·태블릿·데스크톱), 테마 |
| 연결 | 메트릭 서버 목록·연결 상태, 상태 스냅숏과 SSE 갱신, 여러 서버 합쳐 보기 |
| 세션 | 세션 목록과 세션 상세의 **뼈대** — 세션 id·제목·상태·마지막 활동. 모든 플러그인이 세션 id 를 공통 키로 쓴다 |
| 내 차례 | 사람이 처리할 항목을 모으는 수신함. 항목은 플러그인이 넣고, 코어는 모아 세고 배지를 단다 |
| 설정 | 설정 틀과 **플러그인 관리**(켜기·끄기·버전·권한) |
| 사용 기록 | 어떤 슬롯·화면이 쓰이는지(`ausage`) — 플러그인 단위로 집계 |

### 플러그인이 기여하는 자리 (슬롯)

| 슬롯 | 와이어프레임 표시 `data-slot` | 예 |
| --- | --- | --- |

### 정하지 않은 것 (와이어프레임 뒤 설계 단계)

- 패키지 형식: `plugins/<id>/plugin.json`(id·이름·버전·필요한 코어 버전·기여 슬롯·권한) + 화면 모듈(ES module) + 서버 쪽. 서버 쪽을 Rust 단일 바이너리 안의 기능 모듈(빌드 시 포함)로 둘지, 별도 프로세스 수집기(명령·HTTP)로 둘지.
- 플러그인 사이 의존(`qa-review` → `worktrees`·`orca`)과 데이터 공유 범위.
- 배포: Pages 정적 페이지가 켜진 플러그인만 불러오는 방식.

## 모듈형 화면 — 화면은 패널의 배치

플러그인 컨셉을 화면 단위까지 내린다. **화면 하나 = 패널 모듈의 배치**이고, 사용자가 패널을 더하고·빼고·옮기고·크기를 바꿔 화면을 직접 짠다.

- **패널(`panel` 슬롯):** 플러그인이 내는 독립된 상자. 머리(끌기 손잡이 · 제목 · 제공 플러그인 · 메뉴)와 본문. 크기 단계 S·M·L 마다 보여 줄 양을 스스로 정한다(예: 테스트 패널 S = 실행 중 수와 막대, L = 실행 목록과 케이스).
- **배치(코어):** 12열 격자(`wf-grid12`, 패널은 `--span` 열 · `--rows` 행). 데스크톱·데스크톱 세로·태블릿은 자유 배치, Duo 앱은 한 열(접힘)·두 열(펼침)로 자동으로 흘린다.
- **화면 = 배치 프리셋 + 사용자 수정.** 홈·에이전트·결정 같은 기본 화면도 프리셋 배치일 뿐이다. 기기 단계(Duo 접힘 / 펼침 / 태블릿 / 데스크톱 / 데스크톱 세로)마다 배치를 따로 저장한다.
- **화면 편집 `compose`:** 편집 모드에서 패널 외곽이 점선이 되고 모서리로 크기를, 손잡이로 위치를 바꾼다. 「패널 추가」 목록은 켜진 플러그인이 내는 패널들(이름 · 플러그인 · 크기 단계 미리보기). 새 화면(탭)을 만들어 내비게이션에 올릴 수 있다.
- 와이어프레임: 패널은 `<section class="wf-module" data-slot="panel" data-plugin="<id>" style="--span:6;--rows:3">` + `.wf-mhead` + `.wf-mbody`. 편집 상태는 `class="wf-editing"` 을 감싼 요소에.

## 오케스트레이션 시각화 — 한눈에 많이

오케스트레이션(코디네이터 → 태스크 → 워커, 그 사이의 메시지·결정 게이트)이 이 대시보드의 중심 정보다. 시안 A 는 목록 위주라 구조가 잘 안 보였다. 시안 B 는 아래 규칙으로 다시 그린다.

- **모양 = 역할:** 코디네이터(Run)는 띠(레인)의 머리, 태스크는 노드, 워커는 칩(`wf-chip`, 안의 글자 = 에이전트 종류 C·X), 드라이버는 띠 묶음 머리. 결정 게이트는 노드 사이의 문(◆).
- **색 = 상태, 어디서나 같게:** 실행 초록 · 대기/입력 대기 주황 · 실패/막힘/응답 없음 빨강 · 완료 회색 · 취소 흐리게 취소선(`wf-x`) · 메시지 보라.
- **선 = 관계:** 실선 = 선행(deps), 가는 회색 = 띄움(부모→자식), 보라 점선 = 메시지(ask·reply·worker_done), 빨강 = 이탈 경로.
- **밀도:** 한 Run 은 **한 줄 요약**으로 먼저 — 목표 · 진행 분절 막대(`wf-seg`, 태스크마다 한 칸, 상태 색) · 워커 칩 줄 · 대기 질문/게이트 수 · 경과 · 비용. 펼치면 DAG. 숫자는 고정폭, 표는 `wf-dense`. 데스크톱 세로는 Run 10개 이상이 스크롤 없이 보이게.
- **주의가 먼저:** 막힘·응답 없음·질문 대기·게이트 대기를 가진 Run 이 위로, 다 끝난 Run 은 「완료 N」 한 줄로 접힌다.
- **폭별:** 데스크톱·세로는 레인 + DAG + 옆 패널(선택한 노드)을 한 화면에. 태블릿·Duo 펼침은 레인 목록 + 선택한 Run 의 DAG 두 칸. Duo 접힘은 Run 한 줄 요약 카드 목록 → 누르면 DAG(가로 스크롤 아닌 세로로 흐르는 단계 목록). 반접힘은 페이지 = Run 목록, 시트 = 선택한 Run 의 DAG·워커.

### 시안 B 명세 (오케스트레이션 · 모듈형)

- **에이전트 `agents` B — 오케스트레이션 보드:** 패널 배치 화면. 기본 프리셋: ① 「Run 레인」 패널(L, 가장 넓게) — Run 마다 한 줄 요약 레인, 펼친 Run 은 레인 안에 태스크 DAG(노드 = 태스크, 상태 색, 노드 위 워커 칩), 레인 오른쪽 끝에 메일함 표시(질문 n · 완료 보고 n). ② 「주의」 패널(M) — 막힘·응답 없음·게이트 대기 노드 목록. ③ 「단독 세션」 패널(S) — Run 밖 세션 카드 압축. ④ 「활동 타임라인」 패널(M) — 시간축 위 워커 막대(간트). 이어지는 화면: run, session, chat, new-agent, compose.
- **코디네이터 상세 `run` B:** 머리 = Run 한 줄 요약(크게). 본문 패널: 「태스크 DAG」(L, 노드 사이 deps 실선, 게이트 ◆, 재시도는 노드 안 점), 「워커 간트」(M, 워커마다 막대, 메시지 점 보라), 「메일함」(M, ask·reply·worker_done 스레드, 답하지 않은 질문 위), 「워커 표」(M, `wf-dense`: 이름·종류·모델·상태·경과·턴·비용). 노드를 고르면 옆(좁으면 시트)에 그 태스크의 워커·결과·로그. 이어지는 화면: session, decide(게이트), talk.
- **상호작용 `talk` B — 시퀀스 다이어그램:** 에이전트마다 세로 생명선(머리에 역할·종류·상태), 메시지는 생명선 사이 가로 화살표(종류별 표시: 질문 · 답 · 완료 보고 · 에스컬레이션), 시간은 아래로. 코디네이터 묶음 고르기, 종류 필터. Duo 접힘은 생명선 대신 대화 목록. 이어지는 화면: session, run.
- **세션 상세 `session` B:** 머리 아래에 「이 세션의 자리」 띠 — 드라이버 › 코디네이터(Run) › 태스크 › 이 워커, 같은 Run 의 다른 워커 칩. 본문은 패널(계획 · 테스트 · 메일 · 로그 · 만든 문서), 각 패널은 플러그인 제공. 이어지는 화면: run, chat, decide.
- **홈 `home` B — 모듈형 대시보드:** 프리셋 패널: 「내 차례」(M), 「오케스트레이션 요약」(L: 진행 중 Run 들의 한 줄 요약 레인 압축판), 「테스트」(S), 「QA 파이프라인」(S), 「비용」(S), 「플랜 사용량」(S). 머리 오른쪽에 「화면 편집」. 이어지는 화면: decide, agents, run, tests, worktrees, compose.
- **화면 편집 `compose` (오버레이):** 홈 B 를 편집 모드로 깐 위에 「패널 추가」 시트(플러그인별 패널 목록 · 크기 단계 S·M·L 미리보기 · 「추가」), 상단에 「완료 · 취소 · 기본 배치로」와 기기 단계 선택(이 배치는 「데스크톱」용). 이어지는 화면: plugins, home.

| 기본 내비게이션 5 | 홈 `home` · 에이전트 `agents` · 결정 `decide` (메일함 포함, 대기 수 배지) · 리뷰 `worktrees` · 테스트 `tests` |
| 도구 (데스크톱 사이드바 아래쪽 / 그 밖은 「더 보기」) | 프로젝트 `projects` · 설계문서 `designs` · 워크트리 `trees` · 실기기 `devices` · 녹화 영상 `media` · 비교·비용 `compare` · 플랜 사용량 `usage` · 상호작용 `talk` · 워크플로 캔버스 `canvas` · 캐릭터 `chars` |
| 상세 | 세션 상세 `session` · 코디네이터 상세 `run` |
| 오버레이 | 에이전트와 채팅 `chat` · 새 에이전트 `new-agent` · 더 보기 `more` · 화면 편집 `compose` · 설정·메트릭 서버 `settings` · 플러그인 관리 `plugins` |

- 기본 내비게이션 5개 중 코어는 홈·에이전트뿐이다. 결정·리뷰·테스트는 플러그인이 `nav` 슬롯으로 넣은 것이고, 어떤 플러그인이 기본 자리를 차지할지는 설정에서 고른다. 「더 보기」는 나머지 플러그인 화면이 저절로 모이는 곳이다.
- **홈은 코어 화면**이고 내용은 거의 전부 슬롯이다: 위에 내 차례(`inbox`), 그 아래 홈 타일(`home.tile`).
- **에이전트·세션 상세도 코어**다: 카드 줄과 상세 탭은 플러그인이 채운다(`session.badge`·`session.tab`).

## 화면별 명세

형식: **왜 오나** · **먼저 보일 것** · **누르는 것** · **이어지는 화면**(`data-to`) · **폭별 메모** · 현행 참고.

### 홈 `home`
- **왜 오나:** 열자마자 「지금 내 차례가 있나, 무엇이 막혔나」를 안다.
- **사이드바 없음 (2026-11-27):** 홈은 사이드바·레일 없이 그린다. 홈 자체가 메뉴다 — 코어 화면과 설치한 플러그인의 메뉴(`nav` 슬롯)가 모두 카드로 나오고(「메뉴 추가」 카드 → 플러그인 관리), 플러그인을 더하면 카드가 생긴다. 사이드바에 있던 「새 에이전트」·「설정」은 머리 줄로 옮긴다. 다른 화면은 공통 셸(사이드바)을 그대로 두고 「홈」으로 돌아온다. iPhone Duo 앱은 하단 탭 바를 유지한다. 시안 A 는 진행 요약 아래 「메뉴」 카드, B 는 맨 아래 고정 「메뉴」 패널(코어, 지울 수 없음), C 는 메뉴 자체가 본문이고 카드만 둔다(제목 줄 · 묶음 제목 · 반접힘 시트 내용 없음, 설정 · 새 에이전트도 타일) — 모든 메뉴가 같은 크기의 버튼 타일(가로 3 : 세로 4)이다. 위 1:1 칸에 그 화면의 데이터 요약(큰 숫자 · 분절 막대, 기다리는 것이 있으면 모서리 배지), 아래에 이름과 한 줄 상태. 1:1 칸은 비지 않는다 — 데이터가 많은 타일은 모서리에 작은 아이콘, 요약할 데이터가 적은 타일은 화면 아이콘을 크게 가운데 두고 한 줄을 그 아래에. 격자 끝에 노란 라벨을 단 타일 상태 견본(데이터 풍부 · 적음 · 없음 · 기다림 · 오류 · 불러오는 중 · 연결 끊김 · 꺼진 플러그인 · 새 플러그인). 내 차례도 첫 타일(결정 · 보고 · 승인 · 막힘 2×2). 타일은 한 격자에 내 차례 · 기본 내비 · 도구 · 관리 순으로 놓고, 타일에는 `data-menu="<화면 id>"` 를 달아 보드의 「화면 내용」에서 그 화면을 끄면 타일째 숨는다.
- **먼저 보일 것:** ① 내 차례 줄 — 결정 대기 n · 보고 확인 n · 반출 승인 n · 막힘 n (각각 해당 화면으로). ② 진행 요약 — 실행 중 에이전트 수, 실행 중 테스트(진행 막대), QA 파이프라인 단계별 수. ③ 그 밖의 타일(비용·사용량·프로젝트·설계문서)은 작게 한 줄.
- **누르는 것:** 각 줄·타일 → 그 화면. 「새 에이전트」.
- **이어지는 화면:** 모든 메뉴 화면 — decide, agents, worktrees, tests, projects, designs, trees, devices, media, compare, usage, talk, canvas, chars, new-agent, settings, plugins (B·C 는 compose 도).
- **폭별:** 접힘은 내 차례 → 진행 요약 → 나머지 한 열. 펼침·태블릿은 왼쪽 칸 내 차례, 오른쪽 칸 진행 요약. 데스크톱은 세 덩어리 가로. 캐릭터 모드(마을 지도)는 이번 초안에서 그리지 않는다.
- 현행: README 「홈 — 화면 타일」.

### 에이전트 `agents`
- **왜 오나:** 지금 도는 세션들이 괜찮은지, 응답 없음·입력 대기를 찾는다.
- **먼저 보일 것:** 상태별 묶음(응답 없음 → 입력 대기 → 실행 중 → 백그라운드 → 유휴). 카드: 세션 제목, 상태 점, 지금 단계(aplan n/m), 실행 중 테스트 막대, 마지막 활동 시각. 코디네이터는 워커를 접어 품는다.
- **누르는 것:** 카드 → 세션 상세. 「Orca 에서 열기」, 「채팅」, 보기 전환(코디네이터 트리 · 워크트리별 · 타임라인), 필터(Orca 에 열린 것만).
- **이어지는 화면:** session, run, chat, new-agent.
- **폭별:** 펼침 이상은 왼쪽 목록 + 오른쪽 선택한 세션 요약(상세로 가는 버튼). 반접힘은 시트에 보기 전환·필터.
- 현행: README 「에이전트 탭 보기」.

### 결정 `decide`
- **왜 오나:** 에이전트가 기다리는 질문에 답한다. iPad·휴대폰의 핵심 일.
- **먼저 보일 것:** 가장 오래 기다린 질문 하나를 크게 — 질문 머리, 본문, 선택지(권장안 표시), 기다린 시간, 어느 세션인지. 아래에 남은 질문 목록. 탭: 대기 / 메일함(자리 비운 동안 쌓인 것) / Bash 권한.
- **누르는 것:** 선택지 → 「답 보내기」(한 손으로, 엄지 닿는 아래쪽). 「세션 보기」. 메일함 모드 켜기/끄기.
- **이어지는 화면:** session.
- **폭별:** 접힘은 질문 하나가 화면을 채우고 답 버튼은 아래 고정. 펼침은 왼쪽 목록 + 오른쪽 질문. 반접힘(노트북)은 위 반쪽 질문 본문, 아래 반쪽 시트에 선택지와 답 버튼.
- 현행: README 「결정 버튼」·「메일함 모드」.

### 리뷰 `worktrees`
- **왜 오나:** QA 티켓마다 워크트리를 열어 보고 리뷰 완료·반출 승인·머지를 누른다. Mac 의 핵심 일.
- **먼저 보일 것:** 묶음(에픽) 머리 — 단계별 수, 자동화 상태. 티켓 줄 — 키, 제목, 8단계 트랙과 「다음: 누가 무엇을」, 리뷰 상태, 저장소 줄(앞선/뒤처진 커밋, 바뀐 파일).
- **누르는 것:** 「웹으로 보기」(티켓 아래로 웹 VS Code 펼침), 「리뷰 완료 · 반출 승인」(확인 창), 「PR 머지」, 「데스크톱 에디터로 열기」, 거르기(리뷰 상태 · Jira 상태 · QA 단계).
- **이어지는 화면:** trees, session (코디네이터·워커 칩).
- **폭별:** 데스크톱은 티켓 목록 + 펼친 웹 VS Code 가 넓게. 태블릿·펼침은 목록 + 오른쪽 티켓 상세(웹 VS Code 는 데스크톱 전용이라 「Mac 에서 열기」 안내). 접힘은 티켓 목록과 승인 버튼만.
- 현행: README 「워크트리 리뷰」.

### 테스트 `tests`
- **왜 오나:** 도는 테스트가 어디까지 왔고, 무엇이 실패했는지 본다. iPad 에서 오래 띄워 둔다.
- **먼저 보일 것:** 실행 중 — 라벨, 진행 막대, 남은 시간, 「▶ 지금 실행 중인 케이스」. 그 아래 끝난 실행 — 판정(통과·실패·확인·의도한 빨강·실행 오류), 실패 케이스와 메시지.
- **누르는 것:** 실행 → 케이스 칩 펼침, 「세션 보기」, 기간·종류·결과 필터.
- **이어지는 화면:** session.
- **폭별:** 태블릿·펼침은 왼쪽 실행 목록 + 오른쪽 선택한 실행의 케이스. 접힘은 실행 중 카드가 맨 위.
- 현행: README 「atest — 테스트 진행 기록」.

### 워크트리 `trees`
- **왜 오나:** Orca 저장소마다 워크트리 상태(미커밋·앞선 커밋)를 훑고 열거나 지운다.
- **먼저 보일 것:** 저장소별 워크트리 줄 — 브랜치, 상태, 마지막 커밋, 메모.
- **누르는 것:** 에디터로 열기, 웹으로 보기, 삭제(확인), 메모.
- **이어지는 화면:** worktrees.
- 현행: README 「읽는 데이터」의 워크트리 목록.

### 프로젝트 `projects`
- **왜 오나:** 볼트 프로젝트의 진행률과 지금 스텝을 본다.
- **먼저 보일 것:** 프로젝트 카드 — 진행 게이지, 현재 스텝, 연결된 설계문서.
- **이어지는 화면:** designs.
- 현행: README 「프로젝트 진행 API」.

### 설계문서 `designs`
- **왜 오나:** 설계문서를 읽고, 어느 세션이 어느 절을 참조했는지 본다. Mac 에서 화면 시간 14%.
- **먼저 보일 것:** 왼쪽 문서 목록(많이 읽힌 순), 오른쪽 문서 본문과 절마다 참조한 세션 수.
- **이어지는 화면:** session.
- 현행: README 「설계문서」.

### 실기기 `devices`
- **왜 오나:** 실기기·시뮬레이터를 어느 세션이 쓰는지, 화면을 라이브로 본다.
- **먼저 보일 것:** 기기 카드 — 이름, 종류, 쓰는 세션, 대기열. 「화면 보기」.
- **이어지는 화면:** session.
- 현행: README 「실기기 · 에뮬레이터」.

### 녹화 영상 `media`
- **왜 오나:** 에이전트가 남긴 녹화를 휴대폰·태블릿에서 본다. 웹 사용의 대부분.
- **먼저 보일 것:** 플레이어(크게) + 타임라인(케이스·라운드 구간), 아래 영상 목록(종류·프로젝트 필터, 검색).
- **누르는 것:** 재생, 10초 건너뛰기, 재생 속도, 「타임라인과 함께 전체 화면」, 타임라인 구간 → 그 시점.
- **폭별:** 접힘은 플레이어 위, 목록 아래. 펼침 세로는 위 칸 플레이어·아래 칸 타임라인이 아닌, 주름을 피해 왼쪽 칸 플레이어 + 오른쪽 칸 타임라인·목록. 반접힘(노트북)은 위 반쪽 플레이어, 아래 반쪽 시트에 타임라인과 조작 — 이 화면의 대표 자세.
- 현행: README 「녹화 영상」.

### 비교 · 비용 `compare`
- **왜 오나:** 세션·서버별 비용과 토큰을 비교한다(드물게).
- **먼저 보일 것:** 기간 선택, 합계, 시간대별 비용 막대, 세션 표.
- **이어지는 화면:** session.

### 플랜 사용량 `usage`
- **왜 오나:** 계정별 한도(5시간·주간)가 얼마 남았는지 본다.
- **먼저 보일 것:** 계정마다 한도 게이지와 초기화 시각.

### 상호작용 `talk`
- **왜 오나:** 코디네이터와 워커가 주고받은 메시지를 본다(드물게).
- **먼저 보일 것:** 묶음(코디네이터)별 대화 줄, 보낸 이·받는 이 필터.
- **이어지는 화면:** session.

### 워크플로 캔버스 `canvas`
- **왜 오나:** 워크플로 캔버스(별도 서버)의 실행과 그 결정을 본다(드물게).
- **먼저 보일 것:** 실행 목록 + 캔버스 미리보기 자리, 기다리는 결정.

### 캐릭터 `chars`
- **왜 오나:** 캐릭터 모드의 캐릭터를 고르고 배정한다(0회 사용).
- **먼저 보일 것:** 캐릭터 격자와 배정 상태. 최소한으로 그린다.

### 세션 상세 `session`
- **왜 오나:** 세션 하나가 무엇을 하고 있고 막혔는지 본다.
- **먼저 보일 것:** 머리 — 제목, 상태, 모델, 비용, 워크트리. 계획(aplan 단계 체크), 실행 중 테스트, 그 세션의 결정 대기 질문(있으면 맨 위). 탭: 요약 · 로그 · 채팅 · 만든 문서.
- **누르는 것:** 「Orca 에서 열기」, 「채팅」, 결정에 답하기, 닫기.
- **이어지는 화면:** chat, decide, agents(뒤로).
- 현행: README 「세션 상세」.

### 코디네이터 상세 `run`
- **왜 오나:** 코디네이터가 띄운 워커들의 진행을 한눈에.
- **먼저 보일 것:** 체크박스 흐름(태스크 단계), 워커 표(이름·상태·현재 일·결과).
- **이어지는 화면:** session.
- 현행: README 「코디네이터 상세」.

### 에이전트와 채팅 `chat` (오버레이)
- 세션 위에 뜨는 대화 창. 메시지 목록 + 아래 입력창. 접힘은 전체 화면 시트, 넓은 화면은 오른쪽 패널.

### 새 에이전트 `new-agent` (오버레이)
- 저장소·워크트리(새로/기존)·에이전트(claude·codex)·모델·프롬프트를 고르고 띄운다. 다 하면 에이전트 화면.
- **이어지는 화면:** agents.

### 더 보기 `more` (오버레이)
- 도구 화면 10개의 목록. 각 줄에 그 화면의 한 줄 요약 값(예: 녹화 3개 새로).
- **이어지는 화면:** projects, designs, trees, devices, media, compare, usage, talk, canvas, chars.

### 설정 · 메트릭 서버 `settings` (오버레이)
- 코어 설정: 메트릭 서버 목록(연결 점, 켜기, 합쳐 보기/서버별 보기), 내비게이션 위치, 테마. 그 아래 플러그인마다 설정 절(`data-slot="settings"`).
- **이어지는 화면:** plugins.

### 플러그인 관리 `plugins` (코어)
- **왜 오나:** 어떤 기능을 붙이고 뺄지 정한다.
- **먼저 보일 것:** 플러그인 목록 — 이름, 켜짐, 버전, 기여하는 슬롯(nav·home.tile·inbox… 칩), 최근 30일 사용량(ausage), 의존 플러그인. 켜면 무엇이 생기는지 미리보기.
- **누르는 것:** 켜기·끄기, 설정으로, 「설치」(패키지 주소·폴더).
- **이어지는 화면:** settings.
